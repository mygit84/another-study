# NutriOS Landing — спецификация для реализации

> Документ для AI-кодагента. Источник требований: «NutriOS — Landing Brief».
> Читай целиком перед началом работы. При конфликте приоритет такой: **§2 Safety → §11 Acceptance criteria → остальное**.

---

## 0. TL;DR для агента

Собери одностраничный адаптивный лендинг NutriOS из 10 секций на **Vite + React + TypeScript**, стили — **SCSS (CSS Modules)** плюс Tailwind CSS для декоративных фонов, без CSS-in-JS. Главный визуальный элемент — интерактивное демо будущего приложения (app-shell) на статических mock-данных. Бэкенда нет. Весь текст — на русском, лежит в одном файле контента. Медицинских обещаний в коде, тексте, alt-атрибутах и мета-тегах быть не должно; это проверяется автоматическим скриптом в CI.

## 1. Контекст продукта

- **NutriOS** — Personal Nutrition OS: wellness- и образовательный ассистент для планирования питания.
- Учитывает цели самочувствия, вкусы, ограничения, историю питания и бытовой контекст (время, семья, бюджет, поездки).
- **Не медицинский сервис.** Не лечит, не ставит диагнозы, не назначает медицинские диеты, не гарантирует похудение.
- Позиционирование: «Ваш личный навигатор по питанию — без диет, давления и медицинских обещаний».

## 2. Safety — жёсткие требования (блокирующие)

### 2.1 Запрещённый контент

Нигде на странице (текст, `alt`, `title`, `aria-label`, `<meta>`, OG-теги, JSON-LD, mock-данные демо, комментарии в разметке) не допускается:

- обещания лечения, профилактики или облегчения заболеваний;
- диагнозы, «определение дефицитов», интерпретация анализов;
- медицинские, лечебные, клинические диеты;
- гарантии похудения, конкретные килограммы, сроки результата;
- фото «до/после», «идеальные тела», цифры веса в отзывах;
- калорийные цели и цифры веса в mock-данных демо;
- формулировки, что NutriOS заменяет врача, диетолога или нутрициолога;
- стыдящая лексика о еде: «вредная еда», «читмил», «запрещённые продукты».

### 2.2 Стоп-слова (проверяются скриптом)

Создай `scripts/check-copy.ts` (или `.mjs`), который сканирует `src/content/**` и собранный и пре-рендеренный HTML (`dist/**/*.html`) на вхождения (регистронезависимо, по основе слова):

```
лечит, лечение, вылеч, диагноз, диагност, терапи, клинически, гарантир,
гарантия результата, детокс, похуде, сбросить вес, минус кг, жиросжиг,
читмил, вредная еда, запрещённ, заменяет врача, заменит врача, медицинская диета
```

Исключения — только внутри дисклеймера и FAQ, где эти понятия **отрицаются**. Реализуй через allowlist по ключу контента (`disclaimer.*`, `faq.medical.*`), а не через игнор всего файла. Скрипт возвращает ненулевой код выхода при нарушении и подключён к `npm run lint` и CI.

### 2.3 Обязательные элементы

- **Дисклеймер** в футере и в ответе FAQ про медицину, дословно:
  > NutriOS не является медицинским сервисом и не заменяет консультацию врача. При заболеваниях, беременности, расстройствах пищевого поведения и перед существенными изменениями питания обратитесь к специалисту.
- **Safety-плашка** внутри демо app-shell (см. §6.5).
- Блок «Принципы и безопасность» (секция 7).
- Пометка **18+** рядом с финальным CTA и в футере.
- Ссылки в футере: «Политика конфиденциальности», «Условия использования» (пока заглушки `#privacy`, `#terms`).

## 3. Технический стек

| Слой | Выбор | Примечание |
| --- | --- | --- |
| Сборка | Vite 5+ (`npm create vite@latest -- --template react-ts`) | Чистый SPA, без серверного кода |
| UI | React 18+ | Функциональные компоненты, хуки |
| Пре-рендер | `vite-react-ssg` (одна страница `/`) | Нужен для SEO: в `dist/index.html` должна лежать готовая разметка всех секций, а не пустой `<div id="root">`. Клиент гидрирует её. Если `vite-react-ssg` не подходит — свой `scripts/prerender.ts` на `react-dom/server` (`renderToString` → вставка в `dist/index.html`, на клиенте `hydrateRoot`) |
| Язык | TypeScript, `strict: true` | |
| Стили | SCSS (`sass`) + CSS Modules (`*.module.scss`) | Токены — CSS custom properties, правила в §8.6. Tailwind CSS v4 (без preflight) допустим для декоративных анимированных фонов; цвета — только через токены. **styled-components, emotion — запрещены** |
| Компоненты | Собственные, без UI-китов | Допустим `lucide-react` для иконок |
| Анимации | CSS-переходы и `@keyframes`; `framer-motion` — только в демо, через `React.lazy` | Уважать `prefers-reduced-motion` |
| Шрифт | `Manrope` (или `Inter`) через `@fontsource-variable/manrope`, подмножества `cyrillic` + `latin` | Self-hosted, без Google Fonts CDN; `font-display: swap` |
| Тесты | Vitest + Testing Library (юнит), Playwright (e2e + a11y через `@axe-core/playwright`) | e2e гоняется против `vite preview` |
| Линт | ESLint + Prettier + Stylelint (`stylelint-config-standard-scss`) + `scripts/check-copy` | |

`package.json` scripts (минимум):

```json
{
  "dev": "vite",
  "build": "tsc -b && vite-react-ssg build",
  "preview": "vite preview",
  "lint": "eslint . && stylelint \"src/**/*.scss\" && tsx scripts/check-copy.ts",
  "test": "vitest run",
  "test:e2e": "playwright test"
}
```

`check-copy` после сборки дополнительно запускается на `dist/` в CI (`npm run build && tsx scripts/check-copy.ts --html dist`).

**Правила:**

- Ни одной строки пользовательского текста в JSX — всё через `src/content/ru.ts`.
- Каждый компонент — папка: `Name.tsx` + `Name.module.scss` + `index.ts`. Стили одного компонента не импортируются в другой.
- Код, который трогает `window`, `document`, `matchMedia`, `IntersectionObserver`, выполняется только в `useEffect` — иначе сломается пре-рендер.

## 5. Секции страницы

Порядок фиксирован. Каждая секция — `<section id="...">` с `aria-labelledby` на свой заголовок.

### 5.1 Header (sticky)

- Логотип-текст «NutriOS» слева.
- Якорные ссылки (≥1024px): Как работает · Возможности · Демо · FAQ.
- Кнопка CTA справа (текст — §7, вариант hero). На мобильных — только логотип + CTA.
- Фон становится непрозрачным с лёгкой тенью после скролла > 8px.

### 5.2 Hero — `#hero`

- **H1:** «Питание, которое подстраивается под вашу жизнь»
- **Подзаголовок:** «NutriOS учитывает ваши цели, вкусы, ограничения и расписание — и собирает понятный план питания на неделю со списком покупок и объяснением каждого решения»
- Основной CTA + микротекст «2 минуты · бесплатно · без карты».
- Вторичный CTA «Посмотреть, как это работает» → плавный скролл к `#demo`.
- Справа (≥1024px) / снизу (mobile): статичное превью `<AppShell variant="preview" />` — компонент демо в режиме «только просмотр», вкладка «План недели».
- H1 — единственный `<h1>` на странице.
- A/B-варианты H1 храни в `content.hero.titleVariants` (массив), выбор по `config.heroVariant` (по умолчанию индекс 0):
  1. «Питание, которое подстраивается под вашу жизнь»
  2. «Ваш личный навигатор по питанию. Без диет и давления»
  3. «Перестаньте думать, что приготовить. Начните понимать, что вы едите»
  4. «Один план вместо десяти приложений»

### 5.3 Проблема — `#problem`

- Заголовок: «Дело не в силе воли»
- Подзаголовок: «Просто ни один инструмент не собирает всю вашу жизнь в один понятный план питания»
- 4 карточки-боли:
  1. «Что приготовить сегодня?» — каждый вечер одно и то же решение.
  2. «Опять доставка» — план был, но жизнь пошла иначе.
  3. «Советы противоречат» — в интернете сто правил, и все разные.
  4. «Трекеры утомляют» — цифры, ручной ввод и чувство вины.

### 5.4 Как это работает — `#how`

Три шага, горизонтально на desktop, вертикально на mobile, с номерами:

1. **Расскажите о себе** — цели самочувствия, вкусы, ограничения, время и бюджет. Один раз.
2. **Получите план** — меню на неделю, список покупок и объяснение к каждому блюду.
3. **Корректируйте вместе** — «нет времени», «пришли гости», «пустой холодильник»: план подстроится.

### 5.5 Возможности — `#features`

Сетка 3×2 (desktop) / 1 колонка (mobile). Каждая карточка: иконка, заголовок, одна строка описания, клик → переключает демо на соответствующую вкладку и скроллит к `#demo`.

| --- | --- | --- | --- |
| profile | Расскажите о себе один раз — NutriOS запомнит | Цели, вкусы, ограничения, бюджет и навыки готовки в одном профиле | `profile` |
| week | План на неделю за 10 минут | Меню, в котором легко заменить любое блюдо | `week` |
| shopping | Список покупок, который знает ваш холодильник | По отделам, с учётом того, что уже есть дома | `shopping` |

## 6. Компонент AppShell (демо будущего приложения)

Это ключевой элемент: лендинг должен выглядеть как витрина реального приложения, а не абстрактного «AI-ассистента».

### 6.1 API

```ts
type AppShellTab = 'today' | 'week' | 'shopping' | 'recipes' | 'history' | 'learn' | 'profile' | 'context';

interface AppShellProps {
  variant: 'preview' | 'interactive'; // preview: без кликов, без фокуса (aria-hidden + inert)
  initialTab?: AppShellTab;           // default 'today'
  assistantOpen?: boolean;            // default true на desktop
}
```

Состояние активной вкладки поднимается в контекст `DemoContext`, чтобы карточки возможностей (§5.5) могли его переключать.

### 6.2 Раскладка (desktop ≥1024px)

```
┌──────────────────────────────────────────────────────────────┐
│ NutriOS                         Поиск · уведомления · профиль│  header 48px
├────────────┬──────────────────────────────┬──────────────────┤
│ Сегодня ●  │                              │ Ассистент        │
│ План недели│      Рабочая область          │ Почему это блюдо?│
│ Покупки    │      (активная вкладка)       │ Быстрые правки   │
│ Рецепты    │                              │ [Спросить…]      │
│ История    │                              │                  │
│ Обучение   │                              │                  │
│ Профиль    │                              │                  │
├────────────┴──────────────────────────────┴──────────────────┤
│ Wellness и обучение · не медицинский сервис · данные под контролем│ safety bar
└──────────────────────────────────────────────────────────────┘
  sidebar 200px          main 1fr                 assistant 260px
```

- Внешняя рамка: скруглённое «окно» `border-radius: var(--radius-lg)`, тень `var(--shadow-window)`, фон `var(--surface)`.
- Раскладка — CSS Grid: `grid-template-columns: 200px 1fr 260px; grid-template-rows: 48px 1fr auto;` (классы в `AppShell.module.scss`).
- Высота фиксированная: 560px desktop, внутренний скролл только у рабочей области.

### 6.3 Раскладка (mobile <768px)

- Сайдбар скрыт; внизу таб-бар из 5 пунктов: Сегодня, Неделя, Покупки, Ассистент, Профиль.
- Панель ассистента открывается как bottom-sheet по тапу на «Ассистент» или «Почему это блюдо?».

## 8. Дизайн-система

### 8.1 Настроение

Спокойно, тепло, по-бытовому. Натуральные цвета, много воздуха, реальная еда в иллюстрациях, никаких «идеальных тел», фитнес-эстетики, неона и градиентов «AI-магии».

### 8.2 Токены (CSS custom properties в `src/styles/_tokens.scss`, light + dark)

Токены — именно CSS-переменные, а не SCSS-переменные: так тёмная тема работает без пересборки, а цвета доступны в рантайме. SCSS-переменные используются только для того, что нужно на этапе компиляции (брейкпоинты в `@media`).

```scss
:root {
  --bg:            #FBF8F3;  /* тёплый off-white */
  --surface:       #FFFFFF;
  --surface-muted: #F3EEE6;
  --text:          #1F2A24;
  --text-muted:    #5B6660;
  --border:        #E4DDD2;
  --primary:       #2F7D5B;  /* спокойный зелёный, текст на нём белый */
  --primary-hover: #276A4D;
  --accent:        #E9A23B;  /* тёплый янтарный, только акценты */
  --info-bg:       #EAF3EE;  /* safety bar, бейджи */
  --radius-sm: 8px; --radius-md: 12px; --radius-lg: 20px;
  --shadow-window: 0 12px 40px rgb(31 42 36 / 12%);
  --space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px;
  --space-6: 24px; --space-8: 32px; --space-12: 48px; --space-18: 72px; --space-30: 120px;
  --font-sans: 'Manrope Variable', system-ui, sans-serif;
  --ease: cubic-bezier(0.2, 0, 0, 1);
  --duration: 200ms;
}
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #141917; --surface: #1C2320; --surface-muted: #232B27;
    --text: #EEF2EF; --text-muted: #A6B0AA; --border: #2F3833;
    --primary: #5DBB8E; --primary-hover: #74C9A0; --accent: #F0B65C; --info-bg: #1F2E27;

```

Hex-цвета разрешены **только** в `_tokens.scss`; во всех остальных файлах — `var(--…)`. Это проверяет Stylelint (§8.6).

### 8.6 Правила SCSS

**Подключение.** Partials подключаются во все модули автоматически через `vite.config.ts`:

```ts
// vite.config.ts
css: {
  preprocessorOptions: {
    scss: {
      api: 'modern-compiler',
      additionalData: `@use "@/styles" as *;\n`,
    },
  },
  modules: {
    localsConvention: 'camelCaseOnly',
    generateScopedName: process.env.NODE_ENV === 'production'
      ? '[hash:base64:6]'
      : '[name]__[local]__[hash:base64:4]',
  },
},
```

`_index.scss` содержит только `@forward` (`breakpoints`, `mixins`, `typography`) — **никакого CSS на выходе**, иначе он продублируется в каждом модуле. Токены и reset живут только в `global.scss`, который импортируется один раз в `main.tsx`.

**Модульная система Sass.** Только `@use` / `@forward`; `@import` запрещён (deprecated). Встроенные модули — через `sass:map`, `sass:math`.

**Брейкпоинты** (mobile-first):

```scss
// _breakpoints.scss
$breakpoints: (sm: 375px, md: 768px, lg: 1024px, xl: 1440px);

@mixin up($bp) {
  @media (min-width: map.get($breakpoints, $bp)) { @content; }
}
@mixin down($bp) {
  @media (max-width: map.get($breakpoints, $bp) - 0.02px) { @content; }
}
```

Использование: `.grid { grid-template-columns: 1fr; @include up(lg) { grid-template-columns: repeat(3, 1fr); } }`.

**Обязательные миксины** в `_mixins.scss`:

| Миксин | Назначение |
| --- | --- |
| `focus-ring` | `outline: 2px solid var(--primary); outline-offset: 2px;` на `:focus-visible` |
| `visually-hidden` | скрыть визуально, оставить для скринридеров |
| `container` | `max-width: 1200px; margin-inline: auto; padding-inline: var(--space-4)` → `var(--space-6)` от `md` |
| `motion` | оборачивает анимацию в `@media (prefers-reduced-motion: no-preference)` |
| `card` | фон, рамка, радиус карточки (§8.5) |

**Типографика** — миксины `text-h1`, `text-h2`, `text-h3`, `text-body`, `text-small` в `_typography.scss`, внутри уже переключают размер для mobile/desktop по §8.3. Размеры шрифта в модулях напрямую не задаются.

**Нейминг.** Классы в модулях — camelCase-совместимые (`.mealCard`, `.mealCardActive`), в TSX — `styles.mealCard`. Модификаторы — отдельные классы, склеиваются через `clsx`. Глобальные классы (`:global`) — только в `global.scss`.

**Ограничения:**

- Вложенность селекторов — не глубже 3 уровней.
- Без `!important` (кроме `visually-hidden` и reduced-motion reset).
- Без `@extend` — только миксины.
- Без хардкода цветов, отступов кратных 4 и радиусов — только токены.
- Единицы: `rem` для шрифтов, `px` для рамок и брейкпоинтов, токены для отступов.
- Логические свойства (`margin-inline`, `padding-block`) вместо `left/right`, где возможно.

**Stylelint** (`.stylelintrc.json`):

```json
{
  "extends": ["stylelint-config-standard-scss"],
  "rules": {

    "color-named": "never",
    "declaration-no-important": true,
    "max-nesting-depth": 3,
    "selector-max-id": 0,
    "scss/at-import-no-partial-leading-underscore": null,
    "scss/at-extend-no-missing-placeholder": true,
    "selector-class-pattern": "^[a-z][a-zA-Z0-9]+$",
    "at-rule-disallowed-list": ["import", "extend"]
  },
  "overrides": [
    { "files": ["src/styles/_tokens.scss"], "rules": { "color-no-hex": null } },
    { "files": ["src/styles/_mixins.scss", "src/styles/global.scss"], "rules": { "declaration-no-important": null } }
```

## 10. Доступность, SEO, производительность

### 10.1 Доступность (WCAG 2.1 AA)

- Семантика: `header`, `nav`, `main`, `section`, `footer`; один `h1`, логичная иерархия заголовков.

- Все интерактивные элементы доступны с клавиатуры, видимый фокус.
- `prefers-reduced-motion: reduce` → отключить анимации, оставить мгновенные переходы.
- `axe` без нарушений уровня `serious`/`critical`.

### 10.2 SEO и мета

Все мета-теги — статично в `index.html` (не через React), чтобы они были в HTML до запуска JS:

```html
<title>NutriOS — персональный планировщик питания</title>
```

- OG/Twitter-теги с `og.png`; `lang="ru"`; canonical — `// TODO: домен`.

- `robots.txt`, `sitemap.xml` — статичные файлы в `public/`.
- Пре-рендер (§3) обязателен: поисковик и превью соцсетей должны видеть H1 и текст секций без выполнения JS.

### 10.3 Производительность

- Lighthouse (mobile): Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.

- Изображения: `vite-imagetools` (или заранее подготовленные AVIF/WebP), `<picture>` с fallback, явные `width`/`height`, `loading="lazy"` ниже первого экрана, `fetchpriority="high"` для hero.

- Бюджет: JS первого экрана ≤ 120 KB gzip, CSS ≤ 30 KB gzip (проверка `vite build` + `rollup-plugin-visualizer`).
