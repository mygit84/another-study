# Wellness-агент: дизайн

Дата: 2026-10-09

## Цель

Локальный CLI-агент в одном файле, который по задаче пользователя составляет wellness-план (питание, тренировки, восстановление, привычки) с учётом профиля и дневника, а затем проверяет его отдельным агентом-ревьюером. Не медицинский продукт: диагнозы, лечение и лекарства вне зоны ответственности.

## Структура (`agent/`)

| Файл | Назначение |
|---|---|
| `index.ts` | Весь оркестратор, ~120–150 строк, комментарии на русском |
| `profile.md` | Профиль пользователя: цели, ограничения, предпочтения |
| `log.md` | Дневник за 4 дня: еда, сон, тренировки |
| `output.md` | Создаётся агентом при `approve` |
| `package.json` | Свои зависимости: `@openai/agents`, `openai`, `zod`, `tsx` |
| `.env.local` | Уже существует: `PROXYAPI_API_KEY`, опционально `PROXYAPI_MODEL` |

Старый `agent/agent.js` не трогаем.

## Провайдер

- ProxyAPI, OpenAI-совместимый эндпоинт `https://api.proxyapi.ru/v1`.
- Клиент `new OpenAI({ baseURL, apiKey })` → `setDefaultOpenAIClient`.
- `setOpenAIAPI('chat_completions')`: Responses API для DeepSeek через ProxyAPI недоступен.
- `setTracingDisabled(true)`: не отправлять трейсы в OpenAI.
- Модель: `PROXYAPI_MODEL`, по умолчанию `deepseek/deepseek-v4.1-flash`.
- Переменные окружения загружаются из `agent/.env.local` через `process.loadEnvFile`.

## Флоу

1. Задача из `process.argv`; если пусто — подсказка по использованию и выход с кодом 1.
2. Чтение `profile.md` и `log.md`, подстановка в контекст обоих агентов.
3. Раунд `1..3`:
   - Коуч генерирует план. Со 2-го раунда получает свой прошлый план и `issues` ревьюера.
   - Ревьюер получает задачу, профиль, дневник и план; отвечает JSON.
   - Лог: номер раунда, verdict, score, issues.
   - `approve` → запись плана в `output.md`, печать score, выход 0.
   - `needs_human_professional` → сообщение «запрос требует специалиста», выход 0, `output.md` не трогается.
   - `revise` → следующий раунд.
4. После 3 раундов без `approve` — сообщение, что план не одобрен; `output.md` не трогается; выход 1.

## Ревьюер и валидация

Схема Zod:

```ts
z.object({
  verdict: z.enum(['approve', 'revise', 'needs_human_professional']),
  score: z.number().min(0).max(10),
  issues: z.array(z.string()),
})
```

Разбор: снять обёртку ```json, `JSON.parse`, `safeParse`. Невалидный ответ → один повторный запрос с напоминанием «только JSON». Вторая ошибка → исключение, выход 1.

## Промпты (константы в `index.ts`)

- **Коуч:** роль wellness-коуча; формат плана (markdown: цель, план по пунктам/времени, почему так, на что обратить внимание); запрет диагнозов, лечения, лекарств, БАДов, медицинских дозировок; при медицинском запросе — отказ и совет обратиться к врачу.
- **Ревьюер:** критерии — безопасность (нет медицинских советов, экстремальных дефицитов, нагрузок против ограничений), реалистичность, соответствие профилю и дневнику; `needs_human_professional`, если сама задача медицинская (лекарства, диагнозы, симптомы болезни); отвечать только JSON по схеме.

## Вне скоупа

Tools/function calling, UI, серверы, БД, классы, тесты (пользователь проверяет вручную в консоли).
